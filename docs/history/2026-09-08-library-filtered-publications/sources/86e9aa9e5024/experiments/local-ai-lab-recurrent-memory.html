2. O que foi falsificado/parked

A jornada começou em synthetic dense post-hoc Memory Caching. Resultados e falhas metodológicas fizeram essa hipótese ser PARKED. O programa migrou para real recurrent-LM lifecycle, controlou state-load forgetting e então perguntou se snapshots históricos ainda carregavam informação funcional.

Isso é importante epistemicamente: não contamos “quantos experimentos passaram”; preservamos a mudança de hipótese produzida pelos negativos.

4. RNN-06D — próximo gate decisivo

D0 · Recovery Ceiling & Snapshot Schedule Qualification

Randomizar target write; usar schedule fixo de snapshots cego ao target; comparar FINAL, ORACLE-PROXIMAL/BEST diagnóstico e pool histórico fixo. Se oracle-best não superar materialmente final, PARK recovery.

D1 · Parameter-Free Recovery Utility — somente se D0 abrir

Comparar recency, max confidence, min entropy, margin, preregistered confidence×recency, logit ensemble e final+historical mix. Métrica principal: recovered − harmed / N = accuracy(method) − accuracy(final), acompanhada de MiB/ms.

Se ceiling for alto e heuristics fracas, testar um único selector treinado/DART-like. Se heuristics forem fortes, replicar no Mamba oficial antes de qualquer pequeno Qwen GDN.

5. Limites e regras

  • Resultado vale para substrate/configuração qualificados, não para “RNNs” genericamente.
  • Presence não prova economic utility.
  • Oracle é diagnóstico, não método deployável.
  • Não transplantar para Qwen/GDN antes do gate e replication.
  • Experimento permanece isolado da arquitetura tare.tools até haver hipótese de integração explicitamente reconciliada.
